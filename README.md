# 会员行为日志接入环境

这个目录是一套已在运行的接入环境，此前由同事维护，现在交给你继续。

已有的东西：
- `data/warehouse.db`：SQLite 库。表 `events` 是已接入的明细（表上没有任何唯一约束，
  历史导入工具没建）；表 `ingested_batches` 是已接入批次的登记。
- `inbox/`：批次文件（CSV，UTF-8，带表头），共 8 个。上游的文件到达顺序不保证，偶有重投。

运行约定：脚本从仓库根目录以 `python3 ingest.py` 方式运行，数据用相对路径
`inbox/` 与 `data/warehouse.db`。

## 交付物

| 文件 | 说明 |
|------|------|
| `ingest.py` | 接入管道主程序 |
| `tests/test_ingest.py` | pytest 测试，全部在临时目录造数据，不碰真实库 |
| `conftest.py` | 让 `python3 -I -m pytest` 隔离模式下能 import 根目录模块 |
| `report.txt` | 每次运行结束生成的对账报告（运行后出现） |

## 运行

```bash
# 使用默认相对路径（仓库根目录执行）
python3 ingest.py

# 或显式指定路径
python3 ingest.py --inbox inbox --db data/warehouse.db --report report.txt
```

退出码：`0` 表示全部成功（允许有跳过的重传文件）；`1` 表示存在失败批次，
失败批次不入库，已提交的批次不受影响，详见报告第三节。

## 去重与水位设计（为什么这么做）

### 批次身份 = 文件内容指纹，不是文件名，也不是 batch_date

管道对每个 CSV 的数据行做规范化（全字段排序后按无歧义分隔符拼接），计算 SHA-256
作为批次指纹，登记在 `ingested_batches.content_hash`，并建唯一索引兜底。

- **重名重传**：文件名相同、内容相同 → 指纹相同 → 跳过。
- **改名重传**（如 `batch_20251109.csv` 与 `batch_20251109_r1.csv`）：内容一致 →
  指纹相同 → 跳过。即使行顺序被上游打乱，规范化后指纹仍一致。
- **整个目录重跑**：所有文件指纹都已登记 → 全部跳过，库内零新增。
- **内容修正后重投**：哪怕只改一个金额，指纹即变化 → 作为新批次正常接入。

### 为什么不能用 batch_date 当水位跳过

上游不保证到达顺序，晚到批次的 `batch_date` 可能早于已接入的最大日期。
样例中的 `batch_20251104_late.csv` 就是反例：库内已有 2025-11-04 的批次，但这份
晚到文件的 180 行与库内数据完全不重叠，必须接入。若按「最大 batch_date」水位跳过
就会漏数。报告中的「最新批次日期」仅作可读水位展示，不参与跳过判断。

### 为什么不能用 event_id 去重

`events` 表没有唯一约束，且样例数据中存在跨批次的同 `event_id` 不同内容
（同一 event_id 在两个批次里的金额不同），说明 event_id 不是全局唯一键。
管道保持 `events` 表无约束的现状，去重只在**批次内容**这一层做，不按 event_id
跨行去重，避免误删或覆盖业务数据。

### 历史库兼容

老版本 `ingested_batches` 没有 `content_hash` 列，首次运行会自动
`ALTER TABLE ADD COLUMN` 迁移并建唯一索引；历史行该列为 NULL（SQLite 唯一索引
允许多个 NULL），不影响新数据去重。全新库则直接建含该列的表。

## 事务性

每个批次在**单个事务**内完成两步：批量写入 `events` 明细 + 向 `ingested_batches`
登记指纹。任一步失败则整体回滚，不留半个批次的数据，失败后可直接重跑补入。
批次之间相互独立，一个批次失败不回滚此前已提交的批次。

## 金额口径

- CSV 全部按字符串读入，金额用 `Decimal` 基于原始文本累加，不用 pandas 浮点聚合，
  避免 `0.1 + 0.2` 一类的浮点误差。
- 报告金额单位为 CNY，保留两位小数、千分位展示。
- 写入 SQLite 的 REAL 列时才转 float（存储与历史表结构保持一致），对账口径以
  Decimal 重算结果为准。

## 数据校验（非法批次拒绝并不登记）

- 表头缺列、出现未声明列、无数据行；
- 同一文件内 `batch_date` 不唯一或为空；
- `event_id` 为空；
- `amount_orig` / `amount_cny` 不可解析为数字。

## report.txt 对账报告

每次运行结束覆盖生成，四节内容：

1. **本次新接入批次**：批次数、新增行数、新增金额合计，及逐批次明细表；
2. **跳过的已接入/重传文件**：按指纹命中跳过的文件清单；
3. **失败批次**：文件名与原因，没有则为「无」；
4. **累计水位**：已登记批次数、`events` 累计行数、登记行数合计、累计金额合计、
   最新批次日期；当 events 行数与登记行数不一致时输出告警，提示核查历史数据。
